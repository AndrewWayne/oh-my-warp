# Codex 路径输出与多环境识别实验

日期：2026-10-10。产品：oh my warp。

## 结论

相对路径适配有实际价值，但应先确认每个 Codex 会话的真实目录。
本轮模型原始答案偏向绝对目标，实际 Codex TUI 却将文件引用显示成相对路径；
两者不能混为一谈。主仓库和 worktree 中存在同名文件时，使用错误的基准目录
会通过文件存在性校验，并解析到错误副本。

直接从正确目录启动的普通 worktree 在本轮宽窗口引用样本中正常。
`--cd`、Codex 托管 worktree 和窄窗口仍有需要适配的边界。
本轮只进行了后台实验、回放和记录，没有修改应用行为、安装包或公开 release。

## 环境与方法

- 实际安装的 `codex-cli 0.161.0`，模型 `gpt-6.1-sol`，推理级别 `xhigh`。
- 使用独立 `CODEX_HOME`、只读沙箱、禁用共享 daemon、hooks、apps、memories 和多代理；
  保留本机全局 AGENTS 与模型指引，以反映当前用户环境。认证只在私有目录复制，未打印。
- 测试项目有入口脚本、JSON 设置、中文 Markdown 讲义；主仓库、包子目录、linked worktree
  都保留相同的相对文件名，用 `ROOT-A`、`SUB-A`、`ROOT-B`、`SUB-B` 区分内容。
- 每个环境分别要求“读取并说明内容，给出文件引用”和“只输出可复制路径”。
  这两类提示没有指定绝对或相对形式。另有两次明确要求相对路径的对照，不计入倾向统计。
- 模型真实读取 fixture；核对原始答案、Markdown 目标和该轮 `turn_context.cwd`。
  相同 thread 后续恢复可能改变目录，因此目录按本次运行完成时间截取。
- 随后在后台 PTY 恢复这些测试会话，不发送新提示，采集当前 Codex 的真实 TUI 历史显示。
  宽度为 24、40、80、240 列，48 行；不同场景覆盖的宽度见下表。
- `vt100` 解码最终可见行，再送入现有 `GridHandler` 和 `absolute_path_if_valid`。
  使用上一轮已修补的 Mac `omw_local` QA 库，不是未加入补修的已安装公开包。
  另用 `vte` 检查完整 ANSI 流中的 OSC 8 目标与 OSC 7 目录更新。
- 对目录不同的场景，将同一画面分别按真实会话目录和父终端目录解析，检查是否落到同名副本。

这是当前 CLI、模型、配置和受控提示的观察，不是所有 Codex 使用方式的统计调查。
TUI 样本来自恢复后的真实渲染，未覆盖全部流式输出、鼠标事件或平台。

## 模型原始答案

共 21 次模型调用：20 次完成，1 次网络超时后保留记录并重试。
早期两次“非 Git”fixture 实际继承了上层仓库，因此剔除并改用真正的非 Git 目录。
有效主矩阵为 18 份答案：16 份未指定路径形式的答案和 2 份相对路径对照。

| 环境 | 有效答案 | 原始目标与目录观察 | 80 列 TUI 引用回放，使用正确目录 |
| --- | --- | --- | --- |
| 主仓库根目录 | 引用、裸路径各 1 份 | 6 个绝对目标，指向 ROOT-A | 3/3 文件目标找到 |
| 主仓库 `app/` 包 | 各 1 份 | 6 个绝对目标，指向 SUB-A，而非 Git 根文件 | 3/3 |
| linked worktree 根目录 | 各 1 份 | 6 个绝对目标，指向 ROOT-B | 3/3 |
| linked worktree `app/` 包 | 各 1 份 | 6 个绝对目标，指向 SUB-B | 3/3 |
| 主仓库启动，`--cd` 指向 linked worktree | 各 1 份 | 6 个绝对目标，真实目录是 linked worktree | 3/3；父终端目录对照落到 ROOT-A |
| 真正非 Git 普通目录 | 各 1 份 | 6 个绝对目标，指向普通目录 | 3/3 |
| 从主仓库 `exec resume` worktree 会话 | 各 1 份 | 本轮真实目录变为主仓库，6 个目标指向 ROOT-A | 3/3，须按本轮目录判断 |
| Codex `--worktree` 自动创建目录 | 各 1 份 | 6 个绝对目标，指向其私有 worktree | 3/3；父终端目录对照落到主仓库 |

16 份未指定形式的答案中，48/48 个请求文件目标为绝对路径，且都指向本轮真实目录内的正确文件。
两次明确要求相对路径的对照输出 6 个相对路径，按真实目录也都指向正确文件。
不能将本轮 `exec resume` 使用当前目录的行为推广为所有交互式恢复选项的行为。

## 原始目标与终端显示的区别

模型会给出绝对 Markdown 目标，标签可能只是 `src/main.py` 或“入口脚本”。
实际 TUI 将引用渲染为 `src/main.py:1`，或“入口脚本 (src/main.py:1)”等相对文字。
本轮 31 份完成的 PTY 画面均没有 OSC 8 目标和 OSC 7 目录更新。
所以终端仅从可见文字识别链接时，不能直接拿到原始 Markdown 的绝对目标。

31 份画面加 11 个父目录对照共 42 组真实画面回放，全部完成，无待加载样本。
曾遇到 trust prompt 和旧轮次 `Worked for` 干扰，均保留原始证据并重采或修正分析；
这些采集问题没有计为产品失败。

## 已复现的适配缺口

### 会话目录与父终端目录不同

对 `--cd` 和托管 worktree 的 80/240 列文件引用画面：
按真实会话目录解析，三个目标都正确；按主仓库父目录解析，三个目标全部落到主仓库的同名文件。
这比“链接不能点”更值得优先处理，因为错误副本也存在，会通过现有文件校验。
托管 worktree 的 80 列裸绝对路径样本则不受父目录影响，三个目标仍正确。

现有 `terminal/view/link_detection.rs` 的 `scan_for_file_path` 在 alternate screen
取终端记录的当前目录，普通输出取 block 目录；`terminal/view.rs` 的 `pwd_if_local`
从 active block 元数据获取目录。它们没有直接使用本次 Codex 的 `turn_context.cwd`。
回放复现了这一目录选择风险，尚未在生产 GUI 用鼠标确认该场景实际打开错误副本。

### 窄窗口相对路径

| 真实 TUI 输出 | 宽度 | 按正确会话目录找到的请求文件 |
| --- | --- | --- |
| 主仓库、linked worktree、`--cd`、托管 worktree 文件引用，各一组 | 40 列 | 每组 2/3，中文相对路径跨行漏识别 |
| 上述四组文件引用 | 80/240 列 | 每组 3/3 |
| 明确要求相对路径的两组 | 24 列 | 每组 2/3，中文讲义跨行漏识别 |
| 上述两组相对路径 | 40/80/240 列 | 每组 3/3 |
| 主仓库裸绝对路径 | 40 列 | 0/3 |
| 主仓库裸绝对路径 | 80/240 列 | 3/3 |
| linked worktree 子包裸绝对路径 | 40、80、240 列 | 分别 0/3、2/3、3/3 |
| 托管 worktree 裸绝对路径 | 80 列 | 3/3 |

最新补修的完整跨行重建只覆盖绝对路径。相对中文引用仍可能被拆在文件名中间。
另一个新形态是 Codex 在连字符或词边界提前硬换行，例如将 `oh-my-warp` 拆在 `oh-my-` 后，
下一行带缩进。这不满足现有“目录分隔符或接近右边缘”的续行规则，长绝对路径也会漏识别。
linked worktree 的一个 40 列样本还将完整文件引用的一部分识别为已存在的 `src` 目录。

表中“找到”只表示至少某个可见位置能解析到目标，不表示每个字符都具有完整高亮范围、
行号跳转和正确鼠标行为。完整逐格范围另由下面的机械换行实验检查。

## 机械换行补充实验

456 组网格回放覆盖 24、40、80、240 列、soft wrap、机械右边缘 hard wrap、
正确会话目录和错误父目录。机械 hard wrap 不代表全部真实 Codex 词边界换行。

- 48 个绝对目标在每种宽度的 soft wrap 中都逐格得到完整目标和范围。
- 绝对目标机械 hard wrap：40/240 列为 48/48；80 列为 45/48，另三组仍能打开正确文件，
  但部分位置的范围未包括尾部行号；24 列为 46/48，两个托管 worktree 中文路径超出八行限制。
- 六个相对目标在正确目录下：soft wrap 每种宽度 6/6；hard wrap 在 24 列为 4/6，
  其余宽度 6/6。与真实 TUI 的中文引用漏识别相符，但不能替代实际输出测试。
- 错误父目录下的三个相对目标，每种宽度均没有指向预期副本；宽窗口会找到错误同名文件。

## 建议的实现顺序与边界

1. 先为已可靠识别的 Codex pane 确认本轮会话目录，覆盖 `--cd`、托管 worktree 和恢复后的目录变化。
   目录不能仅由最初 `session_meta.cwd`、父进程 CWD 或 Git 根目录推断。
2. 再按该目录扩展相对路径及真实词边界换行重建，保留 `./`、`../`、本地会话校验、
   八行/8192 字节扫描限制和最终文件存在性校验。
3. 用本轮真实输出、同名文件对照和无关续行负例验证后，再做独立 QA 鼠标验收。

正确目录已知时，扩展跨行识别的工作量中等；稳定关联 pane 与会话目录更复杂，也更关键。
不建议自动搜索多个仓库并挑选同名文件。目录来源不可靠时应保守处理，避免让可点击链接指向错误副本。
这些建议尚未实施，原有自定义功能边界和 Windows 行为没有在本轮改动。
